What does an MCP security scan detect?

An MCP audit checks the server definitions your AI tooling trusts, in the same shot as the NSA May‑2026 guidance. MCP connects agents to real capabilities — reading files, running shell, writing to a database. A poisoned or misconfigured server turns that capability into an attack surface. mcp-audit inspects each server definition and flags the patterns that matter.

Where does the attack surface live?

Tool poisoning

Bad actors hide instructions inside tool descriptions. The model reads the tool, and the tool tells it what to do. mcp-audit inspects the text your agents see and flags manipulation markers.

Credential leakage

API keys and tokens hard-coded into MCP configs are the single most common finding. mcp-audit flags key patterns across OpenAI, GitHub, AWS, Slack, JWT, and inline assignments.

Rug-pull supply chain

Registry listing is not a safety signal. A server can pass review and then quietly swap its tool definitions. The commit‑able lockfile detects that drift as a reviewable diff.

How does the rug-pull lockfile work?

mcp-audit fingerprints every server definition into a git-committable state lockfile, then diffs against it on every scan. A tool whose definition changed between audits shows up as a diff in version control — the same shape as a dependency lockfile. No new dashboard, no new process: the change lands in your existing PR review.

# first scan writes the baseline
$ mcp-audit scan . --commit-state     # → .mcp-audit-state.json

# later: a server definition changed — caught as a reviewable diff
$ git diff .mcp-audit-state.json
- "github": "9f2f0c...8d1e"   # was
+ "github": "7ab090...11c3"   # now (possible rug-pull)

Why does offline-first matter for MCP security?

An audit that dies when its cloud is down is a product, not a standard. mcp-audit ships a bundled baseline ruleset and known-CVE registry in every binary, so a scan is always authoritative on its own — even in an air-gapped CI runner or a sovereign, self-hosted environment. A live rules feed is optional enrichment that degrades gracefully to baseline, never a hard dependency.

Is mcp-audit free?

Yes — the core scanner and GitHub Action are MIT-licensed and free. The paid layer is the human-readable audit deliverable and the managed live CVE feed, for teams that want a maintained registry without maintaining one themselves.

MCP security frequently asked questions

What is an MCP server and why does it need a security scan?

MCP (Model Context Protocol) is the open standard that connects AI agents to real tools: filesystems, databases, shell, GitHub, Slack. A misconfigured or malicious MCP server can expose destructive tools, hide instructions in tool descriptions, leak credentials, or exfiltrate data. Because most teams adopt MCP without a security review, scanning before an agent trusts a server is now a routine part of the AI supply chain.

Does mcp-audit need an internet connection to scan?

No. mcp-audit is offline-first: every binary ships a bundled baseline ruleset and known-CVE registry. An audit is always authoritative on its own, even in an air-gapped environment. A live feed is optional enrichment that degrades gracefully to the local baseline if unreachable.

What does the rug-pull detection do?

mcp-audit writes a git-committable state lockfile containing SHA-256 hashes of every server definition. On the next scan it diffs against that snapshot, so a tool whose definition changed between audits shows up as a reviewable diff. This catches rug-pulls: servers that quietly swap a trusted tool for a malicious one.

Is mcp-audit free?

Yes. mcp-audit is MIT-licensed open source and free to use, including the GitHub Action. It ships a bundled baseline ruleset so a scan needs no account and no network. Paid options add a managed CVE feed and a human-readable audit deliverable.

Which MCP security taxonomy does mcp-audit follow?

mcp-audit aligns its detection categories to the NSA's May-2026 MCP security guidance and OWASP's MCP Top 10 classification: hardcoded secrets, tool poisoning, unverified servers, network egress, stale/known-vulnerable versions, and tool-path confusion.
